# クラウド版セットアップ手順（Firebase）

対象: `public/` フォルダのクラウド連携版アプリ
料金: **実質0円**（利用量が無料枠内であれば請求は発生しません。ただし後述の理由で
クレジットカード登録＝Blazeプランへのアップグレードが必要です）

このアプリは Cloud Functions を使わず、ブラウザ（クライアント）側の処理と
Firestore/Storage のセキュリティルールだけで動作します。以下の手順は
すべて Firebase コンソール（ブラウザ）上の操作で完結します。

---

## 1. Firebase プロジェクトを作成する

1. https://console.firebase.google.com/ を開き、Googleアカウントでログイン
2. 「プロジェクトを追加」→ プロジェクト名を入力（例: `animedirec`）
3. Googleアナリティクスは「今は設定しない」でOK（無料枠の使用に影響しません）
4. 作成が終わるまで待つ

> **料金プランについて（重要）**: 新規プロジェクトは初期状態で無料の **Spark プラン** です。
> Authentication・Firestore は Spark プランのままで使えますが、**Cloud Storage は
> Google の仕様変更により、新規プロジェクトでは Blaze プラン（従量課金プラン）への
> アップグレードが必須**になっています（＝クレジットカードの登録が必要）。
> 詳しくは手順4・5を参照してください。**アップグレード＝即課金ではありません**
> （利用量が無料枠内なら請求は0円）。予算アラートの設定（手順5）で安全に運用します。

## 2. Authentication（ログイン機能）を有効化する

1. 左メニュー「構築」→「Authentication」→「始める」
2. 「Sign-in method」タブ →「メール / パスワード」を選択 → 有効にする → 保存

## 3. Firestore Database（データ保存）を有効化する

1. 左メニュー「構築」→「Firestore Database」→「データベースの作成」
2. エディション: **Standard** を選択（Enterpriseは本アプリでは不要）
3. モード: **本番環境モード** を選択（セキュリティルールは後で反映します）
4. リージョン: `asia-northeast1`（東京）を推奨 → 有効にする

## 4. Cloud Storage（写真保存）を有効化する — Blazeへのアップグレードが必要

1. 左メニュー「構築」→「Storage」
2. 「Storageを使用するには、プロジェクトの料金プランをアップグレードしてください」と
   表示されるので、「プロジェクトをアップグレード」をクリック
3. 案内に従って **Blaze プラン**（従量課金）へアップグレードする。ここでクレジットカードの
   登録が必要になる
4. アップグレード完了後、あらためて「Storage」→「始める」を押すと
   「デフォルトバケットのセットアップ」画面が出る。**「料金不要のロケーション」
   （US-EAST1・固定）を選択**する（下記コラム参照）→ 続行 → セキュリティルールは
   デフォルトのまま → 完了

> **ロケーションは「料金不要のロケーション」を選ぶこと（重要）**: 「すべての
> ロケーション」からFirestoreと同じ`asia-northeast1`（東京）を選ぶこともできるが、
> Google Cloud Storageの「Always Free（常時無料）」の対象は米国の一部リージョンに
> 限られており、東京リージョンを選ぶとこの無料枠の対象外になってしまう。
> Storage と Firestore は別サービスなので**リージョンが違っても機能的な問題はない**
> （多少の通信レイテンシは増えるが、本アプリの規模では体感できるレベルではない）。
> 「無料枠を守る」ことを最優先し、Storageは「料金不要のロケーション」を選ぶ。

> **なぜカード登録が必要でも「実質無料」と言えるのか**: Blazeプランは「使った分だけ
> 支払う」プランですが、**Storageの無料枠（5GB保存・1日1GBダウンロード等）はBlaze
> プランの中でも引き続き無料枠として提供されます。** 卒業制作の規模（数十頭・写真は
> 圧縮済み）であれば、この無料枠を超えることはまず考えられません。
> ただし「バグで無限にアップロードし続けてしまった」等の想定外の事態に備えて、
> 次の手順5で**予算アラート**を必ず設定してください。

## 5. 予算アラートを設定する（安全装置・必須）

万一の使いすぎに気づけるよう、少額のしきい値でアラートメールが届くようにします。

1. https://console.cloud.google.com/billing を開く（Firebaseと同じGoogleアカウント）
2. 対象の請求先アカウントを選択 →左メニュー「予算とアラート」→「予算を作成」
3. 名前を入力（例: `animedirec-budget`）→ 対象プロジェクトとして手順1のプロジェクトを選択
4. 予算額を **少額（例: 100円〜500円程度）** に設定
5. アラートのしきい値を **50%・90%・100%** など細かく設定 → 通知先はデフォルト
   （請求管理者への自動メール）のままでOK → 完了

これで、無料枠を超えて課金が発生し始めた場合に**すぐメールで気づける**ようになります。
（あくまで通知であり、自動で利用を止める機能ではない点に注意。心配な場合は
Cloud Functionsで自動停止する仕組みもありますが、本アプリの規模では過剰なため未導入）

## 6. ウェブアプリを登録し、接続情報を取得する

1. プロジェクトの概要ページ（左上の歯車アイコンの少し下）→「</>」（ウェブ）アイコンをクリック
2. アプリの名前を入力（例: `animedirec-web`）。Firebase Hosting はここでは設定しなくてOK
3. 表示される `firebaseConfig = { apiKey: ..., authDomain: ..., ... }` の値をコピー

4. このリポジトリの `public/firebase-config.js` を開き、コピーした値で置き換える

```js
export const firebaseConfig = {
  apiKey: "コピーした値",
  authDomain: "コピーした値",
  projectId: "コピーした値",
  storageBucket: "コピーした値",
  messagingSenderId: "コピーした値",
  appId: "コピーした値"
};
```

> **この値は公開して問題ありません。** Firebase公式もこの値を「秘密情報ではない」と
> 明記しています。実際のアクセス制御は次の手順で反映する `firestore.rules` /
> `storage.rules`（施設・権限のチェック）が行っています。

## 7. セキュリティルールを反映する

Firebase CLI（コマンドラインツール）を使います。パソコンに Node.js がインストールされていれば実行できます。

```bash
npm install -g firebase-tools     # 初回のみ
firebase login                    # ブラウザが開くのでGoogleアカウントでログイン

cd animedirec                     # このリポジトリのルートフォルダで実行
cp .firebaserc.example .firebaserc
# .firebaserc を開き、default の値を手順1で作成したプロジェクトIDに書き換える

firebase deploy --only firestore:rules,storage:rules
```

これで `firestore.rules` と `storage.rules` が反映されます。
（コンソールの「Firestore Database」→「ルール」タブ、「Storage」→「Rules」タブに
直接コピー＆貼り付けして「公開」する方法でも同じ結果になります。CLIが使えない場合はこちらでもOKです。）

## 8. 動作確認（ローカル）

`public` フォルダをそのままブラウザで開いても、`type="module"` の都合上
`file://` では動作しません（CORSエラーになります）。簡易サーバーを立てて確認してください。

```bash
cd animedirec/public
python3 -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

初回は「施設を新規登録」から施設・管理者アカウントを作成してください。
登録後に表示される「施設コード」を、以降のログイン・職員招待に使います。

## 9. インターネット上に公開する（Firebase Hosting）

```bash
cd animedirec
firebase deploy --only hosting
```

コマンド実行後に表示されるURL（`https://<プロジェクトID>.web.app` など）が、
スマホ・PC・タブレットからアクセスできる本番URLになります。Hosting自体の無料枠
（保存10GB・転送360MB/日）は Blaze プランでも変わらず適用されます。

---

## 無料枠を超えないための注意（運用ルール）

- 写真は自動で圧縮してからアップロードされます（コードを変更しないでください）
- 施設全体のバックアップ（「職員管理」→「全データバックアップ」）は、実行するたびに
  全記録を読み込みます。**月1回程度の実行にとどめてください**
- 無料枠の使用状況は Firebase コンソールの「使用状況とお支払い」、または
  Google Cloud Console の「お支払い」から確認できます
- 手順5で設定した予算アラートのメールが届いたら、`docs/backlog.md`に記載の
  「読み取り frugal」設計が崩れていないか（無限ループ的な購読漏れ等）を確認してください

## うまく動かないときは

- ログインできない: メール/パスワード認証を有効化したか（手順2）を確認
- 個体一覧が表示されない: `firestore.rules` を反映したか（手順7）を確認。
  ブラウザの開発者ツール（F12）の Console タブにエラーが表示されます
- 写真が保存されない: Storageを有効化したか（手順4、Blazeへのアップグレード含む）、
  `storage.rules` を反映したか（手順7）を確認
- ゴミ箱やCSV出力でエラーが出る: Firestoreコンソールにインデックス作成を促す
  リンクが表示されることがあります。そのリンクをクリックして作成してください
