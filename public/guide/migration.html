STEP 1

アカウントを2つ用意する

GitHubアカウント

  1. github.com を開き、右上の「Sign up」を押す
  2. メールアドレス・パスワード・ユーザー名を入力し、案内どおりに進める
  3. メールに届く確認コードを入力すれば完了（無料プランでよい）

Googleアカウント

Firebase（この後で使う）はGoogleアカウントでログインして使う。すでに持っていることが多いが、無ければ accounts.google.com から新規作成する。

STEP 2

パソコンに道具を入れる

GitHubを操作する道具を1つと、Firebaseを操作する道具を1つ入れる。

GitHubを操作する道具を選ぶ

おすすめ
GitHub Desktop

コマンド入力なし、画面のボタン操作だけでGitHubを使えるアプリ。この資料はこちらを基準に説明する。

Git（コマンド操作）

ターミナル・コマンドプロンプトに慣れている人向け。gitコマンドで同じことができる。

desktop.github.com からGitHub Desktopをダウンロード・インストールし、起動したら「Sign in to GitHub.com」からSTEP1で作ったアカウントでログインしておく。

Node.js（Firebaseの道具を動かすために必要）

  1. nodejs.org を開き、LTS版をダウンロード・インストール（既定設定のままでよい）
  2. インストール後、コマンドプロンプトを開いて確認する。キーボードの「Windowsキー」（Ctrlの隣にある四角い旗のマークのキー）を押すと画面下に検索欄が出るので、そこにcmdと入力し、表示された「コマンドプロンプト」をクリックして起動する
node --version
npm --version

バージョン番号が表示されればOK。

STEP 3

GitHubへ引っ越す

  1. 1
    今のソースコードを手に入れる

    事前に配布されたZIPファイル（アプリのソースコード一式）を、デスクトップなど分かりやすい場所に展開（解凍）する。ZIPファイルを右クリックし、「すべて展開」を選ぶと展開できる。

  2. 2
    新しいリポジトリを作る

    GitHub Desktopのメニュー「File」→「New repository...」で名前（例: AniMediRec）を入力。Local Pathには、手順1で展開したフォルダを指定する。

    すでに中身が入ったフォルダを指定すると「このフォルダは空ではありません」と聞かれるので、「Add existing repository instead」に進む。

  3. 3
    GitHub上に公開する

    画面上部の「Publish repository」を押す。ログイン中のアカウント名になっていることを確認し、学外に公開したくなければ「Keep this code private」にチェックを入れたまま「Publish repository」。

💡 これで完了

新しいGitHubアカウントの下に、ソースコード一式が入ったリポジトリができた。以降ファイルを変更するたびに、画面下の「Summary」欄に一言メモを書いて「Commit to main」→「Push origin」の2ステップで記録・反映していく。

STEP 4

Firebaseを新しく作る

ここからは真新しいFirebaseプロジェクトを1から作る。

4-1. プロジェクトを作成する

  1. Firebase コンソールを開き、Googleアカウントでログイン
  2. 「プロジェクトを追加」→ プロジェクト名を入力（例: animedirec-新しい名前）
  3. Googleアナリティクスは「今は設定しない」でよい（無料枠の使用に影響しない）
  4. 作成が終わるまで待つ
💡 料金プランについて（重要）

新規プロジェクトは初期状態で無料のSparkプラン。Authentication・Firestoreはこのままで使えるが、Cloud StorageはGoogleの仕様変更により、新規プロジェクトではBlazeプラン（従量課金プラン）へのアップグレードが必須（＝クレジットカードの登録が必要）。詳しくは4-4で説明する。アップグレード＝即課金ではない（利用量が無料枠内なら請求は0円）。

4-2. Authentication（ログイン機能）を有効化する

左メニュー「構築」→「Authentication」→「始める」→「Sign-in method」タブ→「メール / パスワード」を有効にする→保存。

4-3. Firestore Database を有効化する

左メニュー「構築」→「Firestore Database」→「データベースの作成」→エディション: Standard →モード: 本番環境モード →リージョン: asia-northeast1（東京）でよい→有効にする。

4-4. Cloud Storage を有効化する（Blazeプランへのアップグレードが必要）

  1. 左メニュー「構築」→「Storage」→「プロジェクトをアップグレード」から Blazeプラン（従量課金）へアップグレードする（クレジットカードの登録が必要）
  2. アップグレード後、「Storage」→「始める」→「デフォルトバケットのセットアップ」でバケットのロケーションは「料金不要のロケーション」（US-EAST1固定）を選ぶ→続行→セキュリティルールはデフォルトのまま→完了
💡 ロケーションは「料金不要のロケーション」を選ぶこと

「すべてのロケーション」からFirestoreと同じasia-northeast1（東京）を選ぶこともできるが、Google Cloud Storageの「Always Free（常時無料）」の対象は米国の一部リージョンに限られており、東京リージョンを選ぶとこの無料枠の対象外になってしまう。StorageとFirestoreは別サービスなのでリージョンが違っても機能的な問題はない（多少の通信レイテンシは増えるが、体感できるレベルではない）。

💡 なぜカード登録が必要でも「実質無料」と言えるのか

Blazeプランは「使った分だけ支払う」プランだが、Storageの無料枠（5GB-月保存・月100GBダウンロード等）はBlazeプランの中でも引き続き無料枠として提供される。動物数十頭程度のご利用規模（写真は圧縮済み）であれば、この無料枠を超えることはまず考えられない。ただし想定外の事態に備えて、次の手順で必ず予算アラートを設定する。

💡 保存量は「毎月リセット」されない

ダウンロード量や記録の読み書き回数は月が変われば元に戻るが、写真の保存容量（5GB）だけは違う。これは「今何GB分の写真を持っているか」を毎月見て判定する仕組みで、新しい写真を追加するたびに合計は増え続け、削除しない限り減らない。もし合計が5GBを超えた状態が続くと、超えた分だけ毎月わずかな金額（1GBあたり約2円程度）が課金され続ける。圧縮後1枚200〜300KB程度なら、5GBに達するまでに約2万枚必要な計算になり、通常のご利用であれば当面心配は不要。

（正確には）月末時点の残量ではなく、月内の平均保存量で判定される。Googleの公式説明では、保存料金は秒単位で日割り計算される。例えば月の前半は4GB、後半に写真を追加して6GBになった場合、平均はちょうど5GB-月になり無料枠内におさまる。逆に、月末だけ帳尻を合わせて5GB未満に減らしても、それまでの期間ずっと超過していた分はきちんと課金される。実務上は「合計保存量が5GBを超えたら、超えた分だけ課金され始める」という理解で十分。

出典（2026-09時点。Google側の改定で変わる可能性あり）: Firebase Pricing、Cloud Firestoreの料金、Cloud Storageの料金（Always Free）

  1. 続けて、予算アラートを設定する（安全装置・必須）。Google Cloud の請求管理画面を開く（Firebaseと同じGoogleアカウント）→対象の請求先アカウントを選択→左メニュー「予算とアラート」→「予算を作成」
  2. 名前を入力（例: animedirec-budget）→対象プロジェクトとして4-1で作ったプロジェクトを選択
  3. 予算額を少額（例: 100円〜500円程度）に設定
  4. アラートのしきい値を50%・90%・100%など細かく設定→通知先はデフォルト（請求管理者への自動メール）のままでOK→完了
⚠️ 予算アラートの位置づけ

これで、無料枠を超えて課金が発生し始めた場合にすぐメールで気づけるようになる。あくまで通知であり、自動で利用を止める機能ではない点に注意。

4-5. ウェブアプリを登録し、接続情報を取得する

  1. プロジェクト概要ページ→「</>」（ウェブ）アイコン→アプリの名前を入力（Hostingの設定はここでは不要）
  2. 表示される firebaseConfig = { apiKey: ..., ... } の6つの値をコピーする（次のSTEPで使う）

STEP 5

接続情報を書き換える

新しいリポジトリの public/firebase-config.js を開き、STEP4-5でコピーした値に置き換える。

export const firebaseConfig = {
  apiKey: "コピーした値",
  authDomain: "コピーした値",
  projectId: "コピーした値",
  storageBucket: "コピーした値",
  messagingSenderId: "コピーした値",
  appId: "コピーした値"
};

保存したら、GitHub Desktopで「Commit to main」→「Push origin」して変更を記録する。

セキュリティルールを反映する

コマンドプロンプトで、リポジトリのフォルダに移動してから実行する。

npm install -g firebase-tools
firebase login

（ブラウザが開くのでGoogleアカウントでログインする）

copy .firebaserc.example .firebaserc

作成された.firebasercをテキストエディタで開き、defaultの値をSTEP4-1で作ったプロジェクトIDに書き換えて保存する。その後、

firebase deploy --only firestore:rules,storage:rules

を実行すると、権限ルール（firestore.rules・storage.rules）が新しいプロジェクトに反映される。

⚠️ Windowsでの注意

コマンドは1行ずつ実行し、行末に#から始まる説明は付けない（Windowsのコマンドプロンプトは#をコメントとして扱わずエラーになる）。

STEP 6

手元で動作確認する

cd public
python -m http.server 8000

（pythonが見つからない場合はpython3またはpyを試す）

ブラウザで http://localhost:8000 を開き、「施設を新規登録」から施設・管理者アカウントを作成して、記録の追加などひととおり試す。

STEP 7

インターネットに公開する

firebase deploy --only hosting

実行後に表示されるURL（https://<プロジェクトID>.web.app）が本番URL。スマホ・PC・タブレットからアクセスできる。

STEP 8

これからのメンテナンスの流れ

  1. 1
    ソースコードを直す

    public/index.html・public/app.jsなどを編集する。

  2. 2
    変更を記録する

    GitHub Desktopで変更内容を確認し、Summaryに一言書いて「Commit to main」。

  3. 3
    GitHubに反映する

    「Push origin」でGitHub上のリポジトリに反映する。

  4. 4
    動作確認する

    アプリの見た目・動きを変えた場合は、STEP6の方法で手元確認してから進める。

  5. 5
    本番に反映する

    firebase deploy --only hostingを実行する。ルール（firestore.rules/storage.rules）を変えた時はfirebase deploy --only firestore:rules,storage:rulesも忘れずに。

運用の注意

無料枠を超えないための注意

「無料枠」と言われてもピンとこないので、動物50頭・職員5人が使う施設を例に、実際どれくらい余裕があるかを数字で確認する。施設の人に説明する時にも使える目安。

項目この施設での目安無料の範囲余裕
記録・体重の保存（書き込み）1日あたり約110件1日20,000件まで1%未満
記録を見る（読み取り・通常の日）1日あたり約3,000回1日50,000回まで約6%
記録を見る（全データバックアップを押した日）上記込みで約13,000回1日50,000回まで約26%
写真の保存容量（現在の頭数分）約70MB（50頭×5枚）5GB-月まで2%未満
写真の保存容量（無料枠いっぱいまで）—5GB ≒ 写真約1万7000枚相当—
写真を見る（1か月の通信量）数十MB程度月100GBまでほぼ0%

どの項目も無料の範囲の3割以下で、通常のご利用であれば日常的に気にされる必要はない。ただし「全データバックアップ」は毎日ではなく月1回程度に、また表の中で唯一「使うほど積み上がっていく」写真の保存容量だけは、他の項目（毎日・毎月リセットされる）と違って長期的に意識しておくとよい（詳しくはSTEP4-4のコラム参照）。

出典（2026-09時点。Google側の改定で変わる可能性あり）: Firebase Pricing、Cloud Firestoreの料金、Cloud Storageの料金（Always Free）

  • 写真は自動で圧縮してからアップロードされる（コードを変更しないこと）
  • 施設全体のバックアップ（「職員管理」→「全データバックアップ」）は、実行するたびに全記録を読み込む。月1回程度の実行にとどめること
  • 無料枠の使用状況はFirebaseコンソールの「使用状況とお支払い」、またはGoogle Cloud Consoleの「お支払い」から確認できる
  • STEP4-4で設定した予算アラートのメールが届いたら、想定外にデータの読み書きが増えていないか（無限ループ的な購読漏れ等）を確認する

困ったら

うまく動かないときは

ログインできない

メール/パスワード認証を有効化したか（STEP4-2）を確認する。

個体一覧が表示されない

firestore.rulesを反映したか（STEP5の「セキュリティルールを反映する」）を確認する。ブラウザの開発者ツール（F12キー）のConsoleタブにエラーが表示される。

写真が保存されない

Storageを有効化したか（STEP4-4、Blazeへのアップグレード含む）、storage.rulesを反映したか（STEP5）を確認する。

ゴミ箱やCSV出力でエラーが出る

Firestoreコンソールにインデックス作成を促すリンクが表示されることがある。そのリンクをクリックして作成する。

わからない言葉や、もっと詳しく知りたい部分があれば、遠慮なく質問してください。
